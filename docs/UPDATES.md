# 更新与发布

## 使用者

0.8.3 起，普通和极简模式都可进入 **设置 → 应用更新**。

1. 点击“检查更新”，查看公开版本及更新内容。
2. 有新版时点击“下载新版”，可查看进度或取消；下载失败可重新检查后重试。
3. 下载完成并校验通过后，点击“保存并退出安装”。软件保存日程、对话和未提交草稿，退出后覆盖升级并重新打开。保存或校验失败时保留原程序，不开始安装。

旧版首次需从官方 Releases 下载新版安装程序，保存并退出旧版后直接安装，无需卸载。个人记录在 `%APPDATA%\Shixu`，不会随应用文件被替换。可选启动检查默认关闭，保存后从下次启动生效；只检查，不自动下载。正常退出也不会自动安装。

免安装预览和开发环境只支持检查版本。预览版应先退出，再下载并解压完整 ZIP，将原文件夹的“预览数据”完整保留到新文件夹，继续使用原记录；预览数据不会自动转入安装版。不要只替换 exe。

网络无法连接 GitHub 时可继续使用原版本，稍后重试或从官方发布页下载安装包。不要删除个人数据来处理更新故障。发布页缺少自动更新清单时，界面会提供手动下载入口。本机版本高于公开版本时不会降级。

## 维护者

本地改动需要重新构建并发布到 GitHub Releases，安装版才能发现；源码推送本身不构成应用更新。

- 递增 `desktop/package.json` 与锁文件版本，补充 CHANGELOG，测试并提交源码。
- 推送与源码版本一致的稳定标签，例如 `v0.8.3`。发布工作流也支持手动指定已存在的标签。
- 工作流生成 Windows x64 安装包、`.blockmap`、`latest.yml`、免安装 ZIP、源码 ZIP 和 SHA256SUMS.txt，验证后上传草稿，完整上传才公开。
- 手动发布同样必须上传安装包和与它匹配的 `latest.yml`；保留 `.blockmap`。在 `desktop` 运行 `node release-metadata.cjs` 可检查本地产物。
- 已公开的安装包与清单不要替换；递增版本后重新发布，避免已缓存更新与新文件不一致。

更新下载和安装均须使用者点击。客户端同时验证文件大小与 SHA-512，安装前再次验证；当前发行文件尚未代码签名。自动化检查使用本地更新服务器并拦截最终安装调用，不覆盖测试者的实际安装或修改注册表。
